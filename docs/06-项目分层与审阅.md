## 3. 审阅时按这个顺序

1. `schemas/`：请求字段是否合理，哪些输入应被拒绝，返回内容是什么。
2. `api/`：HTTP 地址、参数接收、依赖注入、状态码和返回值。
3. `services/`：预算怎么算，事务如何提交/回滚，版本怎么分配。
4. `models/` 和 `database.py`：字段与约束、数据库连接方式。
5. `tests/`：正常输入、非法输入、故障与持久化是否有验证。

运行调用主线为 **api → services → models / database → PostgreSQL**。纯预算服务只做计算，因此不需要经过数据库。`main.py` 负责把这些组件组装起来；`schemas/` 提供契约，不是额外的网络服务。

M2主线：**Vue对话页 → api/requirements → requirement_service → llm/client → DeepSeek → requirement_merge与schema校验 → Vue需求卡片**。保留命令行抽取入口；对话消息尚未入库。逐文件讲解统一见 [各阶段开发说明](./07-各阶段开发说明.md)。

保持详细中文说明。函数说明使用 `def` 上方的 `"""..."""`，中间空一行；有装饰器时说明放在装饰器上方。新增或修改两三个主要文件后，说明文件职责与调用顺序。

## 4. 这次迁移的对应关系

下表左侧仅用于辨认旧代码位置，不是继续保留的目录。

| 原模块 | 当前模块 |
|---|---|
| `travelmind.main` | `app.main` |
| `travelmind.settings` | `app.config` |
| `travelmind.persistence.database` | 连接函数在 `app.database`，命令入口在 `scripts.check_db` |
| `travelmind.persistence.models` | `app.models.trip` |
| `travelmind.schemas` | `app.schemas.budget` 和 `app.schemas.common` |
| `travelmind.session_schemas` | `app.schemas.trip` |
| 原预算路由 | `app.api.budget` |
| 原会话路由 | `app.api.trips` |
| `travelmind.domain.budget` | `app.services.budget_service` |
| `travelmind.persistence.store.TravelStore` | `app.services.trip_service.TripService` |
| `travelmind.persistence.demo` | `scripts.demo_trip` |

PyCharm 打开项目根目录时，将 `backend` 标记为 Sources Root，并选用 `backend/.venv/Scripts/python.exe`。已安装的项目在其他工作目录也能导入 `app`，不需要在业务代码中修改 `sys.path`。

在 `backend` 下运行：

```powershell
python -m uv sync --locked --link-mode copy
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --env-file .env --reload --host 127.0.0.1 --port 8000
```

旧包导入和旧启动命令不再使用。计算公式、请求/响应结构、接口 URL、环境变量及数据库表名不变。
