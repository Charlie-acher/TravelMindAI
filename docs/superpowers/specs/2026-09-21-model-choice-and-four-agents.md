# 三模型选择与主从四智能体设计修订

> 已被2026-09-21用户确认的[体验优先计划](../plans/2026-09-21-experience-first.md)替代。以下保留为旧设计，不再执行四Agent必交付要求。

日期：2026-09-21。状态：用户要求已纳入开发计划，本文描述待实现目标，不代表已上线。

## 1. 本次范围

- 用户可选择 DeepSeek、Kimi、Qwen 三家文本模型。真实型号由后端配置，前端只提交稳定别名 `deepseek/kimi/qwen`。
- 选择器放在聊天输入框内部底栏、发送按钮左侧，即用户截图中键盘提示附近；窄屏优先保留选择器与发送按钮，键盘提示可隐藏。
- 以用户所选模型为首选；只有故障、熔断或当前能力不可用时才切换备用。不再把正常请求按权重随机分给其他模型。
- 四个智能体按“一个主智能体＋三个子智能体”实施：Coordinator、Research、Planner、Reviewer。需求理解归主智能体；不额外增加第五个 Requirement Agent。
- MiniMax 退出本轮产品和验收范围。已有适配代码属于历史实现，在三模型契约落地时移除对应入口及专用代码；本次文档修订不改运行配置或代码。

## 3. 四个独立智能体

| 智能体 | 自主职责及工具范围 | 返回主智能体的结果 |
|---|---|---|
| Coordinator 主智能体 | 理解用户、澄清、分解任务；按需调用 `delegate_research`、`delegate_plan`、`delegate_review`，汇总回复 | 回复、补问或待发布方案 |
| Research 研究子智能体 | 按需检索共享资料、读取本会话已解析附件、地图查点/周边核对；不编排最终日程 | EvidenceBundle：地点、来源引用、已核实事实、缺口 |
| Planner 规划子智能体 | 使用需求和 EvidenceBundle 编排或修改行程；调用既有预算、日期、候选校验工具 | PlanCandidate：候选草稿、依据、未解决约束 |
| Reviewer 核对子智能体 | 独立读取原始约束、候选和来源，按需调用规则/来源核对工具；不继承 Planner 的内部对话 | ReviewResult：通过、返工意见或需用户取舍 |

每个 Agent 必须有独立的提示词、工具白名单、输入输出结构、内部消息状态和实际模型决策循环。四个角色可以使用同一家模型，也可以运行在同一个后端进程；独立性以实际委派和状态边界验收。

主智能体按任务需要决定调用哪些子智能体：普通聊天可直接答；资料问答通常只调用 Research；完整规划通常 Research → Planner → Reviewer；资料缺口由子智能体返回，主智能体再决定补研究、返工或追问。禁止每条消息机械跑全体，也禁止子智能体递归无限委派。

权限、预算计算、数据校验、返工次数和事务保存仍由程序控制。任何新建/修改行程的候选必须通过程序校验和 Reviewer，主智能体不能绕过发布门槛。最多两次返工；超限或硬约束无法核实，保留旧草稿并暂停询问。保留自然聊天能力，不把普通旅游问答强制变成条件表单。

复用原有外层持久图和业务存储。子任务记录 `run_id/task_id/parent_task_id/agent/status/selected_provider/actual_provider`、时间、结构化结果引用和安全错误类别；不存密钥、完整私密提示或模型隐藏推理。程序验证任务归属与产物版本，旧候选的审核不能用于新候选发布。UI 进度可显示“主智能体正在请研究助手核对地点”，以真实执行事件为准。

## 4. 输入框选择与故障切换

1. 三个名称始终出现在下拉列表。未配置或未完成所需工具能力验证的选项标明原因，不伪装为可用。后端只返回安全的可用状态，不返回密钥和端点。
2. 新会话默认 DeepSeek；会话保存用户选择，刷新后恢复。切换模型不清空聊天、附件、需求或行程。请求创建时冻结 `selected_provider`；默认该轮主/子智能体都遵循这个选择。
3. 运行中修改选择只影响下一次新任务。需要立即换模型时，提供“停止并用所选模型重试”：先取消旧执行并确认停止，再以新执行编号从安全边界重试；不得同时写同一草稿。持久等待的工作流保留原选择，改模型继续也必须显式新建尝试、关联原任务。
4. 相同 `message_id` 重试必须沿用同一选择与输入；变化时报冲突，不能悄悄替换历史执行。历史分别保存所选模型和各次实际使用模型，自动降级不覆盖会话偏好。
5. 首选故障后按服务端固定候选顺序（DeepSeek → Kimi → Qwen，跳过已尝试者）选择已配置、能力兼容且可用的备用；一个执行尝试切换后保持该备用，避免每个子调用反复撞故障首选。新一轮再优先用户选择，受熔断状态约束。
6. 连接错误、超时、429、5xx 等故障触发降级；已知认证/额度问题跳过并给出安全提示；请求参数错误和内容拒绝直接解释，不靠换模型绕过。已有统计、并发与熔断可复用，但健康评分不再覆盖正常用户选择。
7. 故障检测后有备用就立即尝试，不先固定等待同模型完整重试。初始目标：连接超时 3 秒、首个有效模型事件等待 10 秒；检测故障到发起备用请求的应用调度开销不超过 1 秒。实现时用可控时钟测试，再用真实服务核定，不能把这些数值称为当前实测或端到端 SLA。流式中途空闲超时另设上限，取消须释放并发槽位。
8. 对用户已展示正文后禁止跨模型直接续写。中断时保留错误状态，允许重试并明确替换未完成草稿。工具调用参数未收全不执行；工具调用后失败，只能从已保存的安全边界恢复或重放只读工具，避免重复业务写入。
9. 输入框展示当前选择；发生降级时在本轮状态显示“DeepSeek 暂不可用，已切换至 Qwen”。最终结果保留实际使用记录。全部不可用时保留输入与旧方案，允许用户稍后重试。

本轮选择针对文本、结构化与原生工具调用；附件视觉理解和 Embedding 继续使用各自专用配置，不冒充随下拉框切换。上传文字/图片后，后续规划仍遵循用户所选文本模型。

## 5. 实施顺序与完成条件

按小步执行：**M5-C 三模型选择契约和全部调用路径 → M5-D 输入框选择与快速故障切换 → M4-D 主智能体委派三个子智能体 → 联合验收**。M5-C 是四个 Agent 共用的模型基础；M5-D 先交付用户可见收益，再以同一契约完成 M4-D，不另建第二套网关。

- 模拟测试证明所选健康模型不会被随机替换，HTTP/SSE/工具/恢复都使用同一模型上下文。
- DeepSeek、Kimi、Qwen 分别真实验证文本、JSON、流式及必要工具调用；未配置或未通过者如实标注，三家全通之前不宣称“三模型接入完成”。
- 四个 Agent 的真实运行记录能看到父任务委派、子任务独立调用、结构化返回、复核返工和汇总；普通聊天不强制调用子任务。
- 故障注入覆盖首段前后、工具执行前后、手动停止换模、全部不可用、恢复和并发；不重复生成版本，不串用户资料。
- 浏览器在截图对应位置验证选择、切换、状态提示、键盘操作、窄屏、刷新恢复及保留附件；数据库验证选择、实际模型、任务归属与幂等。
