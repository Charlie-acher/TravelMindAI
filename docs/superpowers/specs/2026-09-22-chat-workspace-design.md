# 对话主页面改版设计草案

日期：2026-09-22。状态：用户已确认设计稿，生产接入已实施；数据库迁移、自动检查与真实业务验收见 docs/07 和 docs/08 第12.26节。

交互稿入口：`designs/travelmind-workspace-v2/index.html`。页面、文件职责和设计验收记录见该目录 `README.md`。

## 1. 目标与范围

将 TravelMindAI 的对话主页面改为清晰的旅行工作区：左侧导航和最近对话、中间聊天、右侧状态与文件。用户已确认“个人空间”汇总自己在各对话上传的附件和生成的行程草稿，可预览并返回原对话。

沿用现有 Vue、Arco 组件、绿色主题、账户权限、检索服务和行程快照。参考 Yuxi 的布局与交互，不整体引入其智能体、文件系统或权限框架。

三个方案的取舍：

| 方案 | 效果与代价 |
| --- | --- |
| 推荐：现有业务上重组页面，补齐标题、会话统计和过程持久化 | 满足本次需求，保留旅行规划、附件解析和现有检索能力 |
| 仅调整前端样式 | 改动小，但无法得到真实的会话上下文占用，也无法恢复历史过程 |
| 整体移植 Yuxi 工作区 | 引入大量本次不需要的服务、权限与文件模型，迁移和回归范围过大 |

## 2. 页面结构

桌面布局示意（文字是布局标记，不是演示数据）：

```text
┌────────────────┬────────────────────────────────┬──────────────────────┐
│ TravelMind     │ 当前对话标题                    │ 状态  /  文件        │
│                ├────────────────────────────────┤                      │
│ ＋ 新建对话    │ 用户消息                        │ 最近上下文占用       │
│   个人空间     │                                │ 当前会话累计用量     │
│   知识库*      │ 执行过程                        │ 按模型统计           │
│                │ · 检索知识库：进行中 / 已完成   │                      │
│ 最近     搜索  │ · 读取资料：来源与结果摘要      │ 或                   │
│ 苏州三日游     │ · 查询地图：地点与结果摘要      │                      │
│ 长沙亲子路线   │                                │ 行程草稿与版本       │
│ ……             │ 助手回答 / 行程卡片            │ 本对话上传附件       │
│                │                                │ 文件预览             │
│ 账号菜单       ├────────────────────────────────┤                      │
│                │ 添加附件  输入消息  模型  发送  │                      │
└────────────────┴────────────────────────────────┴──────────────────────┘
* 知识库仅管理员可见。
```

- 左栏约 248px，可收起。所有历史统一归入“最近”，按最后对话时间倒序，保留服务端分页、搜索、重命名和删除。
- 主栏保留当前消息、景点、餐馆和行程卡片。输入框固定在聊天区底部。
- “状态 / 文件”入口固定在对话页右上方，默认收起；右栏展开约 360px，文件预览可扩大。切换会话立即清空旧面板数据，再读取所选会话。
- 窄屏使用覆盖式抽屉，避免三栏挤压正文；关闭后恢复聊天滚动位置。
- 现有管理员“调用费用”入口移入账号菜单，保留全站费用管理功能。
- 图标要求（用户补充确认）：导航、状态、文件、工具组、知识检索和文件读取均配对应的小图标。沿用 ChatIcon 的细线 SVG 风格，常规 18–20px，工具条 16px；图标和文字并列，纯图标按钮提供名称及悬停提示。

## 3. 最近对话与标题

现状：`App.vue` 按今天、昨天、更早分组；`services/requirement/history.py` 在首轮成功时截取原话前 40 字作为标题。

改造：首条消息发出后先显示简短临时标题；首轮回答完成后，结合本轮用户消息与公开回答，生成约 8–20 个汉字的主题标题，例如“苏州三日亲子游”。每个会话自动总结一次，后续可手动改名。

- 标题调用走现有模型网关，记录真实用量；不向模型提供跨会话内容。
- 标题失败保留临时标题，不使已完成聊天失败，不无限重试。
- 保存时再次检查归属与自动命名状态，避免慢请求覆盖用户手动改名；删除后的会话不得重新创建。
- 标题更新不能改变对话排序。旧会话保留原标题，不批量补调模型。
- 新增明确的标题状态字段区分待生成、自动命名和手动命名；既有标题按保留处理。具体迁移与字段约束在实施计划及 docs/08 中列明。

## 4. 个人空间与对话文件

两处使用同一套文件列表和预览能力，区别只在范围：个人空间跨自己的会话，右侧文件仅当前会话。

- 顶部筛选：全部、行程草稿、上传附件；支持文件名搜索和服务端分页。
- 列表显示名称、类型、原对话、更新时间；附件可预览、下载，草稿可预览、下载 Markdown、返回原对话。
- 行程草稿使用已保存的行程快照生成文件视图，不为每次刷新创建一份实体副本。
- 同一草稿按版本归组，默认当前版本，可查看历史版本；撤销后以服务端当前版本为准。
- 草稿中的出发地、日期、人数、预算、来源均取该版本自己的快照。
- 附件按附件编号去重，不将同名文件自动合并。上传未发送的现存附件也按实际状态展示。
- 个人空间不额外加入独立网盘上传、目录管理或分享功能；继续从对话入口上传附件。
- 每次列表、预览、下载均由服务端校验当前用户与会话归属；管理员也不能通过个人空间读取其他用户的私人文件。
- 会话删除后文件入口随之移除；保留底层既有附件清理规则，不改变其生命周期。

## 5. 状态面板与统计口径

现状：已有模型输入、输出、缓存 Token 和逐次用量账本；账本接口为管理员范围，记录尚无可直接用于个人会话隔离的关系。前端仅使用 SSE metrics 中的阶段耗时。

状态面板按当前会话读取，包含：

1. **最近上下文占用**：默认展示本会话最近一次有效聊天模型调用的输入 Token / 该实际模型的上下文窗口；标明模型和调用时间，可切换查看其他实际调用模型。
2. **累计调用**：本会话各模型的调用次数、输入、输出、缓存读取与已知 Token 总量。
3. **最近调用**：模型名称、输入输出与执行状态。

口径要求：

- 上下文占用是最近一次实际调用的输入量，不是整段会话累计 Token。切换输入框模型后，不把旧调用的数据套到新模型。
- 摘要、标题、嵌入等调用单独标注用途；后台标题调用不能覆盖聊天上下文占用卡片。
- 多模型分别统计；缓存读取属于输入 Token 的一部分，不重复相加。
- 模型容量来自经过核对的模型配置；供应商不返回用量或容量未知时显示“暂不可用”，不显示虚构百分比。旧记录缺失统计时明确标记。
- 不照抄截图的“系统提示 / 工具定义 / 内容消息”占比分布；只有将来取得可信的分项 Token 数据后才显示。
- 账目写入需要可信的用户、会话、轮次与调用用途关联；服务端设定归属，不能采信前端传入的用户编号。失败和取消调用也归入正确会话。
- 全局管理员费用与个人会话状态使用不同授权接口；新关联字段、索引、历史记录处理及迁移写入 docs/08。

## 6. 执行过程

参考 Yuxi 的工具时间线和折叠摘要：执行中自动显示当前步骤，完成后收成“已完成 · 调用了 N 个工具 · 用时 …”，可展开查看。

- 展示真实的知识检索、原文读取、联网搜索、地图查询、附件解析、行程生成与校验事件。
- 每条工具记录包括稳定编号、名称、开始/结束状态、可公开的查询摘要、结果数量或短摘要、来源及实际耗时。
- 同一工具的开始和结束更新同一条记录；多次调用保留各自编号，不按工具名错误合并。
- 工具失败、取消、未完成各有状态，不统一标成成功；阶段间隔不冒充工具执行时间。
- 现有 `stage/message` 事件继续兼容；新增结构化事件只从真实执行位置发出。
- 可公开过程随会话保存并在刷新后恢复。旧记录没有过程时不补造；断开、恢复和重试时不重复计数。
- 不展示内部推理、系统提示、密钥、未经筛选的原始工具参数或返回全文。

## 7. 管理员知识库

保持一套现有共享旅行知识库，进入后用两个页签占满主内容区：

**文件管理**：工具栏放上传、文件名搜索、城市和类别筛选；主体改为表格，列出文件名、城市、类别、文件大小、处理状态、更新时间和操作。点击文件打开正文/分段详情，复用上传、解析进度、失败重试、标签编辑和删除能力。统计使用服务端数据，不将当前页数量当总数。

**检索测试**：上方问题输入区，下方可选城市、类别、单文件和返回数量（沿用最多 10 条的限制）；提交后按排名展示命中原文、文件名、页码/章节及检索排序分，支持查看原文。空结果、检索失败与加载状态明确区分。

直接复用 `/api/v1/admin/document-search` 和现有混合检索服务。当前返回分数是混合排序值，不能标成相似度、正确率或重排分；不展示后台未提供的分数。普通账号既看不到入口，也不能直接调用管理或检索测试接口。普通聊天继续使用已有知识问答能力。

## 8. 实施边界与验证顺序

当前工作区位于 main，已有大量未提交修改，包括模型网关、用量统计、行程工作流及前端。后续以这些实际修改为基线，避免覆盖或回退；不把未提交代码当作已经部署的功能。

建议按以下小步实施，每步同步 docs/07 的逐文件说明和 docs/08 的架构/契约变化：

| 步骤 | 主要落点 | 验证目标 |
| --- | --- | --- |
| 导航和知识库页面 | App.vue、chat.css、DocumentPanel.vue、检索测试组件 | 管理员与普通用户入口正确，旧管理功能可用，检索结果可追溯 |
| 自动标题和私人文件 | 会话服务、个人文件聚合接口、文件列表与预览组件 | 标题失败不破坏聊天，手动标题不被覆盖，跨用户拒绝访问，草稿版本正确 |
| 会话状态 | usage 采集/存储、模型配置、会话统计接口和状态组件 | 最新输入和累计量分离，多模型与缺失用量正确，失败/取消可统计 |
| 执行时间线 | events.py、真实工具边界、历史存储和 ThinkingProcess.vue | 实时事件、刷新恢复、取消/失败/重试、来源显示一致 |
| 综合验收 | 后端定向测试、前端构建与浏览器操作 | 新建到成稿、文件预览下载、知识检索、窄屏与账户切换完整走通 |

数据库新增或变更必须先给出迁移，并在 docs/08 维护逐字段字典、主外键、约束、索引及版本。正式检查使用 backend/.env；验收临时文件放 temp/runtime、报告放 temp/reports、日志放 temp/logs。

验证报告分别说明自动化测试、实际数据库/API 检查和浏览器验收结果；没有执行的层次不能写成已通过。本草案只完成代码核对与设计，不代表任何功能已交付。
