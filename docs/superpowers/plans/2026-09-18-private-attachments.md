# D 私人对话附件实施计划

用户授权继续M4下一阶段，并选择复用百炼接入Qwen视觉模型。按09既定顺序先交付D；M4-B修改行程、M4-C持久恢复另行推进。

## 设计与验收

1. 附件契约、独立表和私有上传/读取：复用会话授权、文字解析器；PNG/JPEG/WebP及文字PDF/DOCX/TXT/Markdown，单文件10MiB，每条最多3份。验证跨账号/跨会话拒绝、去重、非法输入、真实迁移和删除。
2. 一个百炼Qwen视觉适配器与文字识别：原件仅发送到已配置模型，不进入公共知识库；结果保存城市、顺序、原文依据、疑点。核验模型格式错误、超限、失败重试，不把识别当作地图核对或可通行证明。
3. 消息集成：先幂等与版本检查，再读取本会话附件；本阶段只解释附件并保留原旅行条件/草稿；成功响应保存附件结果快照，刷新不重跑识别。验证相同消息编号换附件409、冲突不写半轮。
4. 页面：输入框选择/移除附件，发送时携带编号；历史显示识别与受保护原件链接，切换与退出不串会话。验证前端协议和构建。
5. 真实百炼样本、隔离PostgreSQL、静态检查、浏览器检查；07/08记录实际完成范围、数据字典和运行限制。

## 实施裁定

- 在现有codex/m4-a工作区延续未提交成果，不从旧HEAD另起缺少现有实现的工作树，不替用户提交既有改动。
- 按subagent-driven-development技能在合同固定后分配存储与页面，主任务负责模型和聊天集成；审查与测试在汇合后完成。
- D附件轮次不进入规划图，不把读取附件误当作行程修改；界面明确展示此限制。
- 文件统一位于temp/uploads/conversations，以服务端UUID定位；数据库提交失败清理本次新文件。会话删除清理附件记录和原件，不能影响公共资料。
- 状态不保存processing：同步识别结束后保存ready/needs_confirmation/failed，避免进程中断后永久卡住；外部模型调用不持有数据库事务。成功结果可复用，失败可在新请求重试。
