# M4-C：独立审查和持久恢复

用户已要求完成既定 M4。范围依据 03 第 7 节、09 第 13 节；保留 M4-A/B 已验收行为，跨会话偏好不在本步。

## 方案

复用现有聊天业务作为候选生成节点，截获其最终保存请求，先将候选写入 LangGraph 检查点。独立 Reviewer 先重算日期、时间、预算及来源规则，再以独立模型请求检查用户意图。审查通过才调用原事务保存。自动返工最多两次，每次沿用原工具额度；反馈作为数据传入规划器，不能越过程序约束。

图为 `generate → review → publish`，不合格时 `review → generate`，需要取舍或缺项时 `review → wait`。`wait` 使用原生 interrupt；等待回复作为普通历史保存，前端明确展示继续、保留现状，只有程序检查通过的候选可供确认采用。新回复携带同一执行编号和明确选择，用 Command 恢复。旧卡片、跨会话执行号、变更消息编号内容均拒绝。

采用官方 PostgresSaver，业务执行表以会话外键关联；检查点表以执行号关联，删除会话一并清理。DDL 由 Alembic 管理，不在请求中 setup。每会话非阻塞 PostgreSQL advisory lock 防止同一图并发推进，现有行锁和双版本校验继续保护最终写入。

恢复以节点为单位：中途退出的只读查询或模型调用可以重做；已完成候选不重做。publish 节点可能重放，原消息编号幂等保证不会多写行程。进程重启后由原请求重试或用户继续触发恢复，不增加后台常驻执行器。

## 验收

- 自动返工零至两次、预算/日期/冲突/排除项/引用错误不得被模型放行。
- PostgreSQL 持久检查点在重新创建连接和图后恢复；暂停后服务重启，浏览器继续。
- 提交成功但图尚未记录完成时重放，消息与行程各保存一次。
- 越权、过期恢复、重复选择和并发请求有明确结果；普通聊天、附件规划、局部修改、撤销继续通过。
- 同步 07/08 的调用链、字段字典、迁移和实际验收证据。
