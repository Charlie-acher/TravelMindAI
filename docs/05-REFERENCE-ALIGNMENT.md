## 3. 技术清单的采用与差异

| 原文列项 | TravelMindAI 决策 | 阶段/原因 |
|---|---|---|
| Python 3.11/3.12 | 当前以已存在的 Python 3.11.2 建基线 | M0；其他版本通过兼容测试后再支持 |
| FastAPI、Pydantic | 采用，应用工厂 + DTO + 统一错误 | M1 |
| LangChain、LangGraph | 采用；当前环境已是 1.x，锁定兼容版本 | M2/M4；不复制 0.1.x/0.0.x 示例环境 |
| FAISS + Chroma | 继续使用既有 Milvus 方案 | M3；避免同时维护三套向量存储 |
| SQLAlchemy 2、PostgreSQL/SQLite | 采用；PostgreSQL 为集成验收目标 | M1-B；SQLite 不能代替 PostgreSQL 验收 |
| Redis 缓存/会话 | 按需缓存；图状态以 checkpointer 为准 | 不把 Redis 聊天消息等同于图恢复 |
| Celery + Redis | 延后到需要持久任务队列时 | 小文件索引先做可重试后台任务，需 worker 持久执行时再接入 |
| Vue 3、TypeScript、Pinia、Vite | 采用 | M6；已具备前端开发经验，直接实现产品页面 |
| Arco Design Vue | 作为首版组件库 | M6；与参考界面方向一致 |
| TailwindCSS | 非必需，先使用 scoped CSS | 避免为同一布局重复引入样式体系 |
| ECharts | 预算图表按需引入；地图延后 P1 | 图表库不负责提供路线或地理数据 |
| WebSocket / Socket.IO | 首版继续使用 SSE | 单向进度/文本推送；Socket.IO 与原生 WebSocket 不混用 |
| OpenAI / DeepSeek / Qwen | M2 先接一个已配置模型；M5 保留原四提供方目标 | DeepSeek、Qwen、Kimi、MiniMax；OpenAI 为可选扩展 |
| 天气、地图、预订查询 | 天气/地图真实工具 P1；无服务时标为待核实 | 不做下单支付；静态航班/酒店数组不能视作搜索结果 |
| 用户注册、登录、个人资料 | 本地演示先单租户；对外服务前补认证 | `owner_id` 由服务端赋值，不能相信客户端 user_id |

以上为本项目实施选择，不声称是飞书原文要求。原有四提供方目标和 Milvus 不因本次参考文档对照而被替换。

## 4. 示例不能直接作为工程基线的具体原因

以下是原文静态核对结果，没有在本地安装或执行原文项目：

| 原文位置 | 观察到的问题 | 本项目处理 |
|---|---|---|
| §6.1/6.2 配置与数据库 | 默认同步 SQLite URL 与异步引擎示例不配套 | 异步连接选择匹配驱动；资源在生命周期内管理 |
| §4.2 spots SQL | `embedding_id` 为整数，却在该列声明向量距离索引 | 向量写入 Milvus；业务表只保存关联 ID |
| §6.4 需求与行程节点 | 自由文本 JSON 解析缺乏业务校验，草案以 Markdown 为主 | Pydantic 校验 + 领域规则；先产出结构化行程再渲染 |
| §6.5 图编排 | 主路径为固定串联；重试判断函数未挂到条件边，compile 未配置检查点 | 补缺字段/意图路由、有限返工、interrupt 和持久化恢复 |
| §6.5 context 合并 | 允许覆盖初始状态中的任意同名字段 | 仅接受业务字段白名单，身份与内部控制状态由服务端管理 |
| §6.7 天气 | “真实 API”地址为占位域名，失败回退随机天气；温度随机函数传参也不完整 | 接真实供应方前返回 unavailable；fake 只用于测试 |
| §6.4/6.8 路线 | 对检索候选排序而非按实际每日活动优化，结果与展示草案未统一 | 优化当天入选活动，回写同一 itinerary 后重算与审查 |
| §6.9 Embedding | 按非空 key 选择凭据，但 endpoint 随聊天 provider 变化 | 向量化与聊天模型独立配置，禁止混配模型/端点/凭据 |
| §6.9 检索 | 异步函数内执行同步检索，且直接用 `1-score` 当统一相关性 | 使用异步或线程隔离；评分语义随库/度量明确，不当成概率 |
| §6.10 Agent API | 以用户维度读写历史，异常详情直接返回客户端 | 会话隔离、归属校验；统一可读错误与 request_id |
| §7 前端详情 | 行程/航班/酒店为静态示例，部分按钮仅弹出提示 | 以 API 为准；未实现能力不显示虚假的成功状态 |
| §8 依赖/§9 部署 | 依赖版本早于当前环境；代码 import 的 `langchain_chroma` 未在清单中显式声明；Celery 命令指向未展示的入口 | 从实际导入生成依赖并锁定；服务入口与构建均需验证 |

原文展示的最近邻路线是一种启发式排序，不能证明“最优路线”。本项目验收关注少折返、满足时间/预算/排除项，并明确交通耗时是否有真实工具支持。

## 5. 实施接口与验收归属

| 业务产物 | 负责模块 | 验收重点 |
|---|---|---|
| 精确预算 | Domain / M1-A | 单价来源、计价单位、房间/晚数、总额和余额可复算 |
| 结构化需求和集中追问 | Requirement / M2 | 不补造预算；修改保留未变字段；真实抽取评测 |
| 景点资料与攻略引用 | POI/RAG / M3 | 城市与权限过滤；有效 chunk 引用；删除后不可检索 |
| 候选筛选与行程生成 | Research/Planner / M4 | 选择理由、逐日活动、硬约束、结构化输出 |
| 路线调整与审查 | Route/Reviewer / M4 | 只改相关日期；无坐标降级；返工最多 2 次 |
| 会话恢复 | Checkpointer / M4 | 同 thread 恢复，跨 thread 隔离，服务重启验证 |
| 失败降级 | ModelGateway / M5 | 契约、真实 smoke、超时/限流/结构化错误演练 |
| 可操作界面 | Vue / M6 | 真实 API、SSE、活动编辑、引用、保存与导出 |
| 部署与质量 | M7 | 六个 PRD 场景、评测结果、新环境启动 |
